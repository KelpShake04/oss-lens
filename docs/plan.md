## 주제 A: 오픈소스 의존성 보안·라이선스 진단기 (가칭)
문제: 프로젝트가 쓰는 오픈소스 라이브러리의 취약점(CVE)·라이선스 위반을 개발자/학생팀/스타트업이 모름. 스캐너 결과는 영어·전문용어라 이해 어려움.
해결: 폴더/GitHub URL 입력 → SBOM 생성 → 취약점·라이선스 검사 → 로컬 LLM이 한국어로 "위험도·영향·고치는 법" 리포트.
차별화: OSSDoctor(2025 수상, 프로젝트 건강도·기여 지원)와 달리 보안·라이선스 + 한국어 LLM 해설, 코드 외부 전송 없음(로컬).

### 사용 오픈소스 (전부 오픈소스)
- syft 1.55.0 (Apache-2.0): SBOM 생성
- grype 0.121.0 (Apache-2.0): 취약점 매칭
- Ollama + qwen3:8b (설치됨): 한국어 해설. 맥(M1 Pro) 느리면 RTX 3070(VRAM 8GB) PC에서 Ollama 서버 실행 → OLLAMA_HOST로 원격 호출
- 웹 UI: 미정 (Streamlit 또는 단일 HTML 리포트)

### MVP 범위
1. [x] 입력: 로컬 폴더, GitHub URL (`git clone --depth 1`)
2. [x] syft → grype JSON 파싱 (중복 매치 병합, CVSS·EPSS·KEV 반영 위험 점수)
3. [x] 라이선스 충돌 규칙 (GPL·AGPL·LGPL·MPL·상업 이용 제한, SPDX 식 OR/AND/WITH)
4. [x] 상위 위험 항목만 LLM 해설 (기본 5개, 캐시, Ollama 없으면 규칙 기반 설명)
5. [x] HTML 리포트 출력 (단일 파일, 업그레이드 계획·필터·다크모드)
